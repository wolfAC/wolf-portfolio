## Why L1 needed a prerequisite: the layout still had 5 dead ends

Before writing district copy, checked what `CyberCityLayout.js` — the actual road/district layout every placement system reads — still contained. It had 6 `districts` and 6 `alleyNodes`, each carrying an `area` field naming its `Area` class. Cross-referencing against the surviving `Areas.js` registration list (8 entries) found 5 layout slots whose `area` pointed at a class deleted by commit `443974e` (the same commit that dropped the Phase D building system, restored in `phase-d-implementation-notes.md`): `broadcastPlaza`→`social`, `undercroftYard`→`lab`, `skylineObservatory`→`achievements`, `devCircuit`→`circuit`, `archiveSubstation`→`behindTheScene`.

Confirmed via `Roads.js` (builds a radial avenue + gate spur per district, an alley connector per alley node, both unconditional loops over the full layout arrays) and `CyberCityBuildingPlacements.js`/`CyberCityPropPlacements.js` (both scatter buildings/props per *district* the same unconditional way — alley nodes, notably, never got buildings/props at all, only a road connector, even before this trim) that all 6 districts had real roads, buildings, and props, and all 6 alley nodes had a real road connector. So 4 districts and 1 alley node were fully built, driveable dead ends — no signage, no content, nothing to do there.

Presented this to the project owner as a decision (trim vs. revive vs. leave as quiet zones) rather than picking unilaterally, since it changes road topology and total building/prop count, a bigger blast radius than "write some copy." Decision: **trim**. Removed the 4 orphaned `districts` entries and the 1 orphaned `alleyNodes` entry from `CyberCityLayout.js`, leaving 2 districts (`corporateSpire`, `holoBazaar`) and 5 alley nodes.

Checked the remaining nodes' angular spacing before assuming a redesign was needed: the 5 removed districts/alley happened to leave the 7 survivors (2 districts + 5 alleys) already reasonably evenly spaced around the ring (gaps of 30–60°, no large empty arc) — coincidental, but it meant no manual re-layout of angles was needed, just deleting the 5 entries outright.

## The crash this uncovered, and how the two orphaned hero landmarks were saved

`CyberCityBuildingPlacements.js`'s `generateHeroLandmarks()` looks up two of its three unique landmarks by district id via `CYBER_CITY_LAYOUT.districts.find(...)`: `hero-skylineObservatory` (the reserved acid-green beacon) and `hero-broadcastPlaza`. Both looked up districts (`skylineObservatory`, `broadcastPlaza`) that the trim above had just removed — `.find()` returns `undefined`, and the following `.position.x` would throw at **module load time** (`CYBER_CITY_BUILDING_PLACEMENTS = generatePlacements()` runs immediately on import), meaning the game would fail to boot entirely. Caught this by actually executing the generator (bundled with esbuild, run in Node — static `npm run build` type-checks/transforms but doesn't execute module-level code, so it would not have caught this) before considering the layout trim done.

Rather than delete the two orphaned heroes along with their districts — they're unique, hard-won visual content (`phase-d-implementation-notes.md`'s "one-of-a-kind skyline focal points"), and pure landmarks with no dependency on an interactive Area existing — both were relocated:

- **`hero-skylineObservatory`** (acid-green, tallest, the one holding A1's reserved beacon color) now stands just outside the hub (Transit Nexus) at a fixed angle/radius (30°, radius 28) rather than tied to any district — fitting, since a "skyline observatory" beacon visible from the city center is arguably a better fit for the concept than a district street it's not walkable content, an obvious win. Angle 30° was picked because it's the direction the now-removed `archiveSubstation` alley connector used to point — but more importantly, it's clear of both surviving districts' radial avenues (`corporateSpire`@0°, `holoBazaar`@60°), verified by the fact that avenues only exist at exact district angles.
- **`hero-broadcastPlaza`** (cyan) was folded into `holoBazaar` — the one surviving main district that didn't already have its own hero (`corporateSpire` keeps `hero-corporateSpire`).

**Verification performed on the relocation**, not just "it doesn't crash": bundled `CyberCityBuildingPlacements.js` with esbuild and ran it in Node to get the actual generated placement list, then computed pairwise bounding-circle overlaps across all 19 placements. First attempt (a flat `z + 6` offset for `hero-broadcastPlaza`, matching the convention the other two heroes use) landed almost exactly on top of an already-placed regular building (`holoBazaar-1`). Rather than accept that, brute-forced a search over 360° × several radii around `holoBazaar`'s center for the offset with the most clearance from every regular building already placed there, **excluding** the district's gate-spur wedge (`spurAngle ± 35°`, the road entrance — a candidate at 262° looked good on clearance alone but sat inside that wedge and would have blocked the road). Settled on 280°/radius 5 (~3.8 units of clearance, comfortably outside the wedge). Final result: 2 overlap pairs total across all 19 placements — both pre-existing, already documented in `phase-d-implementation-notes.md` as an accepted "known, minor, residual imperfection" of the original 6-district layout (not something introduced by this trim; confirmed by checking that `corporateSpire`'s own placements are first in RNG sequence in both the old and new layout, so its buildings are byte-identical to before). The one overlap this phase's changes could have introduced (the relocated `hero-broadcastPlaza`) was resolved, not just detected.

Also removed `CyberCityBuildingPlacements.js`'s now-dead `DISTRICT_TINTS` entries for the 4 removed districts (unused object keys, harmless but dead).

**Update, post-playtesting:** the project owner reported `hero-skylineObservatory` was blocking sightlines at the hub — the spawn point and busiest, most central spot in the city was exactly the wrong place for the tallest, widest of the three hero landmarks (`midCount: 14`, `halfWidth/halfDepth: 3.2`, both the largest of the three). Removed it outright rather than relocating again. The acid-green reserved beacon color is consequently unused for now (nothing else in the palette is allowed to use it per A1); re-adding a smaller/further landmark to hold it is a reasonable future option but wasn't assumed here. `hero-broadcastPlaza`'s relocation into `holoBazaar` is unaffected. Total placements: 18 (was 19); re-verified via the same bundle-and-run-in-Node approach that this doesn't crash.

## Bonus fix: `EasterArea` was never registered

While reading `Areas.js` to confirm the surviving-area registration list, noticed `EasterArea` is imported at the top of the file but was never added to the `list` array that actually matches glTF nodes to `Area` subclasses — meaning it was dead code (imported, instantiated never) regardless of whether `areasModel.glb` has a matching `easter`-prefixed node. Added it to `list` — a one-line, zero-risk fix: if no matching node exists in the model, this is a no-op (the matching loop simply never fires); if one does exist, this fixes a real bug where a whole area's content was silently never spawned.

## L2/L3/L4: not attempted, each for a different documented reason

- **L2** needs a 3D authoring tool this environment doesn't have — the same constraint every other `[ASSET]` task in this plan has hit (Phases B, D, E, F all substituted procedural generation for authored assets specifically because no tool was available; L2's task is "model unique set-dressing," which doesn't have a procedural substitute the way terrain/buildings/props did).
- **L3** was investigated, not assumed. `phase-l-district-copy.md`'s summary table shows exactly which: `BowlingArea.js`, `AltarArea.js`, `CookieArea.js`, `ToiletArea.js`, `TimeMachineArea.js` all still contain their **original, pre-reskin mechanic and content** — real bowling pins/ball, the original altar, the original cookie-consent-banner joke, a literal toilet cabin with candle flames, an actual TV/time-machine. `CyberCityLayout.js` already carries their new district names (Overclock Arcade, Server Shrine, Glitch Vendor Alley, Malfunction Stall, Chrono Terminal), but the code behind those names hasn't caught up — A2 explicitly calls for replacing Bowling's *mechanic*, not just retexturing it. Rewriting five separate gameplay mechanics (631 + 507 + 516 + 42 + 81 lines) with zero ability to playtest any of them is a fundamentally different risk class from a data retint or a procedural-geometry reskin — every other risky, hard-to-verify decision in this plan (G2's fresnel-over-SSR, K2's vignette-over-chromatic-aberration) was resolved by picking the *lower-risk option*, but there is no lower-risk substitute for "rewrite a mini-game" available here. Left for a session where the result can actually be played.
- **L4** wasn't attempted per explicit direction — the project owner asked to finish the visual/world phases (H–Q) before content work.
